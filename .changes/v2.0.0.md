## dbt-agent-skills v2.0.0 - October 21, 2026

### dbt

#### Features

* Recommend the `latest_version_pointer` workflow (dbt Core v1.12+) and reliably trigger on breaking model changes.
* Add the `maintaining-dbt-documentation` skill — audits dbt documentation coverage (from the dbt manifest) and drafts missing model/column descriptions in the project's own house style, one folder at a time, for human review.
* Add the `querying-the-dbt-information-schema` skill. It teaches agents to answer project-metadata questions on dbt v2 with `dbt show --info` and `{{ info_schema() }}`, and covers query routing, stale metadata locations, JSON-encoded columns, and when runtime views are populated.

#### Fixes

* Clarify MCP config skill setup (token use, authorization header, Claude setup)
* Correct Semantic Layer YAML examples for latest and legacy specs.

### dbt-migration

#### Breaking Changes

* Rename migrating-dbt-core-to-fusion skill to migrating-dbt-core-to-v2

#### Features

* Replace migrating-dbt-core-to-fusion skill with comprehensive triage skill that classifies errors into actionable categories
* Replace the upgrading-dbt-core job-trigger exit gate with an in-session verification gate. On dbt platform it runs a fixed command set (dbt parse, compile, build, test) on the develop session's own credentials; in VS Code it is dbt parse only. Jobs are discovered from the project rather than passed in, and migration_jobs.json is now tracking and reporting only.
* The upgrading-dbt platform profile now reports migration telemetry (stop reasons, verification gate results and the final outcome) through `record_migration_event` when it is available, and the local profile records the run's outcome in target/dbt_migration_status.json when `report` runs, so the VS Code extension can report how a migration ended.

#### Fixes

* Fix gaps in `migrating-dbt-core-to-v2` found during a real production migration — default the repro command to `--static-analysis strict` (plain `dbt compile` was masking real errors), add a case-sensitive/reserved-word identifier mismatch pattern, add warehouse-verification steps to distinguish real bugs from static analysis cache false positives, extend `static_analysis: off` guidance to production models with sign-off guardrails, and flag same-node latent duplicate errors and autofix diff placement issues.
* Fix upgrading-dbt KB guidance for the require_explicit_package_overrides_for_builtin_materializations flag so it only applies when a package overrides a built-in materialization
* Fix migrating-dbt-core-to-v2 autofix review step so it isolates changes made by dbt-autofix instead of diffing against HEAD~1

#### Under the Hood

* Split the upgrading-dbt-core skill's execution mechanics into local and dbt platform profiles, moved its issue corpus to a build-time-compiled kb/ directory, and tightened the optional verify-jobs gate to require per-run approval instead of a fixed attempt cap.
* The upgrading-dbt platform profile now reports migration telemetry through the generic `record_telemetry` tool, with `type` (`GaveUp`, `GateResult` or `Outcome`) and `event_args`, instead of `record_migration_event` with `kind`.

### repo

#### Breaking Changes

* Version the whole repo in lockstep and release in batches. Every plugin, the Tessl tile and the dbt packages now share one version, starting at 2.0.0, which moves only when a release PR is merged. Releases are cut from changie fragments by the "Create release PR" workflow and published as tagged GitHub releases, so `dbt deps` can pin `revision` to a release tag. Feature PRs no longer bump versions; they add a changie fragment that names the plugin as its component. The Claude marketplace now fetches each plugin from a `stable` branch that moves to each release tag, instead of from `main`, so unreleased changes no longer reach marketplace users.

#### Fixes

* Register the `using-dbt-state` skill in `tile.json` so it publishes to the Tessl registry, and fix supporting-file references in `upgrading-dbt-core` and `using-dbt-for-analytics-engineering` that were written as plain text instead of markdown links.

#### Docs

* Add section on usage for skill invocation 
* Fix the CONTRIBUTING.md table of contents, which linked to five sections that do not exist and omitted four that do.

#### Under the Hood

* Removed `scripts/generate_marketplace.py` which generated incorrect marketplace structure
* `tile.json` for Tessl
* Allow this to be installed via pip or other build tools.
* "Publish" GHA for Tessl
* Restructure skills into separate installable plugins (dbt and dbt-migration) using Dagster-style plugin directories, enabling selective installation.
* Publish Tiles only on merge / push to main
* Extend `scripts/validate_repo.py` with checks for the Cursor marketplace manifests, plugin name/version agreement across marketplaces, SKILL.md frontmatter, and `tile.json` version increments.
* Parse SKILL.md frontmatter with PyYAML in `scripts/validate_repo.py` instead of approximating YAML with regexes, which silently accepted malformed frontmatter.
